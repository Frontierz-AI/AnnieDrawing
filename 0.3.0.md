# AnnieDrawing 0.3.0 — host embed and change cursor

Untracked request. Do not merge this file into the public manual. Implement the behavior, then record it in `CHANGELOG.md`, `DECISIONS.md`, and the existing API docs.

This is a **minor** release: new APIs, backward-compatible defaults. Document format stays **version 2**. `CATALOG_VERSION` does not change unless a built-in kind’s create/read contract changes. Aliases are not new kinds.

## Why

Hosts that put this board next to a live voice or chat agent need four things 0.2.x does not give them:

1. A cheap answer to “what changed since I last looked,” without re-reading the whole scene or attaching a large image.
2. Agent edits that a person does not undo with the ordinary undo key.
3. A small raster image that fits a realtime data channel (about 240 KiB).
4. An embed that does not assume `1rem = 16px`, does not open project documentation, and does not fetch pasted website URLs.

Do this by extending `createBoard`, `createDoc`, `apply`, `describe`, `export`, and `on('change')`. Do not add a second document model, a second operation language, or new agent tool names.

## Constraints

- Implement from this file and the current public types. Do not read, port, translate, or paraphrase another drawing editor. Independently authored code, fixtures, and icons only (`AGENTS.md`).
- Do not use another product’s name, component names, store names, or file format in code, docs, comments, or tests.
- Default bundle stays at most five direct runtime dependencies and **under 100 KiB gzip**, including CSS. A new `anniedrawing/fellow` entry may live outside that budget. JPEG encoding belongs in `src/porter` and may be a separate async chunk if that is what keeps the default bundle honest.
- Headless `anniedrawing/core` stays free of DOM at module load. Raster export may keep throwing in Node, as PNG does today.
- Origin remains provenance, not authentication.
- Failed **non-lenient** batches still change nothing.

## Non-goals for 0.3.0

- New MCP or `board_*` tools. Existing tools may grow optional fields listed below.
- Format version 3, multiplayer, a network backend, or persisted revision in `.annie`.
- HTML items, video items, or unfurl behavior changes (except hosts already passing `unfurl: false`).
- Teaching “layers,” extra pages as scenes, or a laser pointer.
- Changing the six tool names.

## 1. Session revision and `changesSince`

Add a monotonic **session** counter. It is not a catalog version and not a history index.

### Rules

- New document: `revision === 0`.
- Each successful, non-`dryRun` `apply` that commits at least one operation increments `revision` by **1** (one committed transaction, not one op).
- `load()` and `clear()` reset `revision` to `0` and forget per-item session stamps.
- History trim (`LIMITS.maxHistory`) must **not** rewind or reuse `revision`.
- Do not write `revision` into compact `.annie` JSON.

### API

On `DocModel` and `Board`:

```ts
readonly revision: number;

changesSince(since: number, options?: { origin?: string | 'user' | 'agent' }): ChangeLog;
```

```ts
interface ChangeLog {
  /** Current session revision (read this after the call). */
  cursor: number;
  since: number;
  changes: ChangeSlice[];
}

interface ChangeSlice {
  revision: number;
  origin: string;
  label?: string;
  ops: Op[];
}

interface ChangeEvent {
  ops: Op[];
  inverse: Op[];
  origin: string;
  label?: string;
  /** Session revision after this commit. */
  revision: number;
}
```

`changesSince(since)` returns slices with `revision > since`, oldest first.

`options.origin`:

- omitted: every committed origin
- a string: exact origin match (`user`, `api`, `agent:fellow`)
- `'agent'`: any origin that starts with `agent:`

Unknown or future `since` values (including `since >= revision`) return `{ cursor, since, changes: [] }`.

Keep a compact session log of committed slices so `changesSince` still works after a history entry is dropped. Cap the session log at **500** slices. If a caller’s `since` is older than the retained log, return:

```ts
{
  cursor,
  since,
  changes: [],
  truncated: true,
}
```

Add `truncated?: true` only in that case. Hosts that see `truncated` must call `describe()` or `read()`, not assume the board is unchanged.

`undo` / `redo` are committed transactions: they increment `revision` and appear in `changesSince` with their existing undo/redo labels.

### `describe({ since })`

Extend `DescribeOptions`:

```ts
interface DescribeOptions {
  // existing fields unchanged
  since?: number;
}
```

When `since` is set, list only items created, last written, or removed after that revision.

- Removed items: one line `removed <id>` (brief) or `removed <id> <kind>` (normal/full). Do not resurrect the old geometry.
- Still-present items: same line format as today.
- Respect existing `maxItems`, `scope`, `page`, `detail`, `relations`, `freeSpace`.
- Empty delta: `No changes since revision <since>.`

Track last-written revision per item in session memory only.

Headless `board_describe` / `DescribeSchema` accept optional `since`.

## 2. Host-stamped agent name

`apply({ agentName })` already labels the visiting cursor. Hosts need a default so an agent tool call cannot pick the label.

```ts
interface BoardOptions {
  /** Used when origin starts with `agent:` and apply() omits agentName. */
  agentName?: string;
}
```

- `apply({ agentName })` wins for that batch.
- `createBoard({ agentName: 'Alex' })` then `apply(ops, { origin: 'agent:fellow' })` shows **Alex**.
- Trim whitespace. Empty string is “no name,” same as today.
- Headless `createDoc` ignores this option (no cursor).

Do not treat `agentName` as an origin or as authorization.

## 3. Agent history: keep teaching work off ordinary undo

Today an `agent:` batch is a normal history entry. A person pressing undo erases it.

```ts
interface BoardOptions {
  /**
   * `shared` (default): current behavior.
   * `hidden`: default undo/redo skip origins that start with `agent:`.
   */
  agentHistory?: 'shared' | 'hidden';
}

interface DocOptions {
  agentHistory?: 'shared' | 'hidden';
}
```

When `hidden`:

- `undo()` / `redo()` with no origin walk only non-`agent:` entries.
- `undo({ origin: 'agent:fellow' })` still undoes that origin (already implemented).
- Keyboard undo in the browser editor uses `undo()` with no origin, so it follows this rule.
- Agent batches still emit `change`, increment `revision`, and appear in `changesSince`.
- `canUndo` / `canRedo` reflect what the **default** undo/redo would do.

`createDoc` must support the same option so hosts can test it without a DOM.

## 4. Reveal created items and a quieter visiting cursor

### Camera

AnnieDrawing does not move the camera after `apply`. Hosts that cannot see a new batch need an official hook.

```ts
interface ApplyOptions {
  /** After a successful browser apply, fit the camera to created item ids. */
  reveal?: 'none' | 'fit';
}

interface BoardOptions {
  /** Default reveal for origins that start with `agent:`. Default `none`. */
  agentReveal?: 'none' | 'fit';
}
```

Resolution: `apply.reveal` if set, else `agentReveal` when origin starts with `agent:`, else `none`.

`fit` uses the existing `view.fit(createdIds)` path. If every created id is already inside the viewport, do not move the camera. If created ids are on another page, do not change page and do not move the camera (same as today’s cursor rule). Headless apply ignores `reveal`.

Dry runs never reveal.

### Presence

```ts
interface AgentPresenceOptions {
  /** On-screen non-connector stops before the rest appear together. Default 8. */
  maxStops?: number;
  /** Multiplier on move and reveal durations. Default 1. Minimum 0.25, maximum 2. */
  durationScale?: number;
}

interface BoardOptions {
  agentPresence?: boolean | AgentPresenceOptions;
}
```

`agentPresence: false` still disables the walk. `true` and omitted stay at today’s 8 stops.

The document still commits before the walk. Do not add sleeps for agents.

## 5. Lenient apply

Voice hosts often receive one bad object in an otherwise good batch. Atomic apply is the right default. Offer an opt-in.

```ts
interface ApplyOptions {
  /**
   * When true, invalid operations are skipped and the rest commit as one
   * transaction. Default false (all-or-nothing).
   */
  lenient?: boolean;
}

interface ApplyResult {
  ok: boolean;
  created: string[];
  errors: { index: number; code: string; message: string }[];
  warnings: { index: number; code: string; message: string }[];
  /** Present only when lenient: operations that did not commit. */
  skipped?: { index: number; code: string; message: string }[];
}
```

When `lenient: true`:

- Validate each op as today. Failed ops go to `skipped` (and may also be listed in `errors` with the same objects — prefer **`skipped` only**, keep `errors` empty if anything committed).
- Later ops in the same batch may reference ids created earlier in the batch **if those earlier ops committed**.
- If at least one op commits: `ok: true`, one history entry, one `revision` step, one change event.
- If none commit: `ok: false`, `skipped` filled, document unchanged (same as a failed atomic batch).
- `dryRun` + `lenient` reports what would be skipped without writing.
- `OVERLAPS_EXISTING` remains a warning on committed creates.

When `lenient` is omitted or false: current behavior. `skipped` is omitted.

Do not add `lenient` to `runTool` / `board_apply` in 0.3.0. Hosts that want it call `apply` themselves.

## 6. Budgeted JPEG / WebP export

```ts
type ExportFormat = 'json' | 'svg' | 'png' | 'jpeg' | 'webp';

interface ExportOptions {
  scope?: Scope;
  scale?: number;
  background?: string | boolean;
  padding?: number;
  labels?: boolean;
  /** Longest output side in CSS pixels. Ignored for json/svg. */
  maxSide?: number;
  /** If set, run a quality/scale ladder and return the smallest result that fits. */
  maxBytes?: number;
  /** Starting JPEG/WebP quality, 0.1–1. Default 0.85. */
  quality?: number;
}
```

- `export('jpeg' | 'webp', options)` returns a `Blob` in the browser.
- Build from the same SVG path as PNG, then rasterize.
- If `maxSide` is set, downscale so `max(width, height) <= maxSide` before encoding.
- If `maxBytes` is set, step quality down (0.85 → 0.7 → 0.55 → 0.4), then reduce scale by half (minimum scale 0.25) and retry. Return the smallest blob produced. **Do not throw** because the budget was missed; the host checks `blob.size`.
- `labels: true` keeps today’s item-id labels (needed when a vision model must point back at JSON ids).
- The Export **menu** does not gain JPEG/WebP in 0.3.0. Programmatic `export` only.
- Headless / Node: reject with the same class of error PNG uses today.
- `board_snapshot` stays PNG. Hosts that need JPEG call `board.export` directly.

Suggested host values (not library defaults): `maxSide: 1280`, `maxBytes: 245760`.

## 7. Embed chrome and CSS pixels

### UI

```ts
interface UiOptions {
  menu?: boolean;
  export?: boolean | UiExportFormat[];
  /** Page chips, add-page, and All pages. Default true. */
  pages?: boolean;
}
```

`pages: false` hides page navigation. `page.add` / `setPage` still work from JavaScript. The last-page deletion rule is unchanged.

Existing flags already cover menu and export. Embeds should pass:

```ts
{
  ui: { menu: false, export: false, pages: false },
  exposeGlobal: false,
  unfurl: false,
}
```

That combination is valid in 0.2.x except `pages`. Add `pages` only.

### CSS

Library styles under `.ad-root` must size chrome in **px**, not `rem`. Several rules today use `rem` (`3.6rem`, `17rem`, `7.5rem`, …). Convert them at 16px per rem (the size they were written for).

Do not set `html` or `body` font-size. Hosts that use `1rem = 10px` must get the same chrome as a 16px rem page.

Keep `container-type: size` on `.ad-root`.

## 9. Host vocabulary aliases

Some hosts already send a small English vocabulary from an older tool schema. Accept it at the **operation** boundary. Store and serialize **AnnieDrawing kinds and tokens only**.

This is not another editor’s document format. Do not accept foreign schema trees, rich-text documents, or foreign ids as a load path. There is no import for a third-party `.tldr` (or similar) file.

### Kind aliases (`add.item.kind` only)

| Host writes | Stored kind | Extra defaults if the field is omitted |
|---|---|---|
| `rectangle` | `rect` | — |
| `arrow` | `connector` | `heads.end = 'arrow'`, `route = 'elbow'` |

`ellipse`, `note`, `text`, `line`, `connector` already match. Unknown kinds stay unknown (current rule).

`query({ kind: 'rectangle' })` and `query({ kind: 'arrow' })` match the stored kinds above.

Do not add `rectangle` or `arrow` to `KIND_CATALOG`. `kindsSince` does not list aliases.

### Color aliases (`style.stroke`, `style.fill`, and `style` color strings)

Map these **exact** lowercase names to existing AnnieDrawing tokens. Do not add new palette tokens.

| Host writes | Token |
|---|---|
| `black` | `ink` |
| `grey` | `slate` |
| `gray` | `slate` |
| `blue` | `sky` |
| `light-blue` | `sky` |
| `green` | `teal` |
| `light-green` | `moss` |
| `red` | `rose` |
| `light-red` | `rose` |
| `orange` | `coral` |
| `yellow` | `amber` |
| `violet` | `violet` |
| `light-violet` | `violet` |

CSS hex and `rgb()` values keep working as they do today. Unlisted names are unchanged (`color()` already passes unknown strings through).

Compact JSON writes the **token** (`ink`), not the alias (`black`).

### Connector endpoints

`from` and `to` already accept `{ item, side }` or `{ x, y }`. Also accept a **string item id**, meaning `{ item: id, side: 'auto' }`.

```ts
{ op: 'add', item: { id: 'i_link', kind: 'connector', from: 'step1', to: 'step2' } }
```

is valid and stores structured endpoints. Compact JSON writes `{ item, side }`, not the string form.

### Host-chosen ids

Keep today’s rule: callers may supply ids (`step1` is valid; max 160 characters). Do not rewrite them to `i_*`.

### Provenance in describe

If an item’s last session writer had an origin starting with `agent:`, normal/full `describe` appends `, by agent`. If the host set `data.by`, full detail already prints `data.*` — do not invent a second metadata schema.

## 12. Tests (required)

Unit (`anniedrawing/core` where possible):

1. `revision` steps once per committed apply; dryRun does not step; `load` resets to 0.
2. `changesSince(0)` after two applies returns two slices; `changesSince(cursor)` is empty.
3. `changesSince` with `origin: 'user'` hides `agent:x`.
4. After more than 100 history entries, `changesSince` still returns later slices; after 500 session slices, older `since` returns `truncated: true`.
5. `describe({ since })` lists only new/changed/removed ids.
6. `agentHistory: 'hidden'`: `undo()` after an `agent:` apply then a `user` apply undoes the user work only; `undo({ origin: 'agent:x' })` removes the agent work.
7. `lenient: true` commits the good ops and lists the bad index in `skipped`; `lenient: false` still rolls back everything.
8. Kind alias `rectangle` stores `rect`; `arrow` stores `connector` with an end arrow; `query({ kind: 'arrow' })` finds it.
9. Color alias `black` stores `ink` on compact JSON.
10. String endpoint `from: 'a'` stores `{ item: 'a', side: 'auto' }`.
11. `agentPlaceGap: 120` applies when `place.gap` is omitted and origin is `agent:tool`; explicit `gap: 10` wins.

Browser:

12. `reveal: 'fit'` pans to an off-screen create; does not pan when the create is already visible.
13. `createBoard({ agentName: 'Alex' })` labels the cursor without `apply.agentName`.
14. `agentPresence: { maxStops: 1 }` dumps the rest of the batch after one stop.
15. `export('jpeg', { maxSide: 1280, maxBytes: 245760, labels: true })` returns a `image/jpeg` Blob; `labels: true` is visible in a snapshot test.
16. `ui.pages: false` shows no page chips; `setPage` still works.
17. With host `html { font-size: 10px }`, toolbar / inspector hit targets stay within 2px of the 16px-rem measurements (px conversion).
18. `createFellowBoard` applies the preset table in §11.

Keep the gzip budget check green for the default entry.

## 14. What the host will do (do not implement here)

A consuming app will keep its own two tool names, map a small `{ kind, id, x, y, w, h, text, color, from, to }` payload onto `apply`, stamp `origin: 'agent:<role>'`, filter `on('change')` for `origin === 'user'`, attach at most two JPEGs on a data channel, and leave the board mounted while the panel is hidden.

0.3.0 only needs the APIs above so that host stays thin.
