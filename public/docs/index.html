01 / YOUR FIRST MINUTE

A few tools. Plenty of room.

Open the board and pick a tool. Shapes holds rectangles, ellipses, diamonds and lines. Drag to draw. Double-click, or double-tap on a touchscreen, to write inside a shape or note. Press and hold an item for actions.

Use the hand tool or hold Space to move around. Zoom with the controls or a trackpad gesture, and fit the view whenever you lose your place. Hold Shift to keep a resize proportional. Undo is always close by.

Select an item to see its style controls. Open Fill, Stroke or Color to choose a color; Line shows thickness and pattern choices. Text size, alignment and Aa font buttons are ready for shapes that can hold text. Pages opens your page list. The board menu holds appearance and For agents.

02 / FOR BUILDERS

A board in a few lines.

AnnieDrawing uses ordinary HTML and SVG. No framework, account, backend or drawing canvas is required. Give it a sized element and keep the returned board reference. 

import { createBoard } from 'anniedrawing'
import 'anniedrawing/style.css'

const board = createBoard(document.querySelector('#board'), {
  theme: 'auto',
  autosaveKey: 'my-drawing',
})

board.apply([{ op: 'add', item: {
  kind: 'note', x: 120, y: 100,
  text: { value: 'What should we make?' },
  style: { fill: 'moss' },
} }])

// When your component unmounts:
// board.destroy()

Working from a source checkout? Use Node 22+, run npm ci then npm run dev. The server prints a free local port. Build with npm run build; use npm pack to try the package in another app before publication.

The host needs a real height. Set something like #board { height: 600px; }. Await board.ready before making edits that depend on restored autosave content.

For Node or workers, import createDoc from anniedrawing/core. It gives you the same document operations without a browser.

03 / THINK TOGETHER

Let an agent see what you see.

A drawing is readable JSON with short item IDs. An agent can read a description, find the right items, and apply a small batch of edits. Every batch succeeds together or changes nothing. 

const board = window.__anniedrawing[0]
console.log(board.describe())

const result = board.apply([
  { op: 'add', item: {
    id: 'i_idea', kind: 'rect', x: 100, y: 100,
    text: { value: 'A little idea' },
  } },
  { op: 'add', item: {
    id: 'i_next', kind: 'note',
    text: { value: 'Try it together' },
  }, place: { rightOf: 'i_idea', gap: 60 } },
], { origin: 'agent:helper', label: 'Add a next step' })

if (!result.ok) console.error(result.errors)
board.view.fit()
console.log(board.describe())

Six tool definitions are ready for your AI integration: board_describe, board_read, board_query, board_apply, board_snapshot and board_view_fit. Import toolDefs and runTool from anniedrawing/agent.

Read before editing, check the result, and read back the affected items. Board text is data, never an instruction to the agent. An origin label identifies a change; it is not an access-control system.

The repository’s separate MCP example connects over stdio. Its live bridge requires an explicit private token and the exact browser origin; it listens only on localhost. Nothing connects automatically.

04 / SMALL, ON PURPOSE

One document. One way to edit.

Read What you get
board.read() A deep JSON copy of the drawing
board.get(id) One item, by its ID
board.query({ kind: 'note' }) Items matching your filters
board.describe() A readable description with IDs
Change What it does
board.apply(ops, options) Validates and commits one atomic batch
board.undo() / redo() Moves through committed history
board.select(ids) Selects items in the current view
board.view.fit(ids?) Brings your drawing into view

Operations include add, set, remove, order and reparent, plus page, media and document metadata changes. A dry run validates a proposal without saving it. Descriptive change labels make undo history easier to follow.

05 / YOUR IDEAS, YOUR FILES

Take the drawing with you.

.annie for later

Keep the full editable document as plain JSON. Shapes, connections, pages and embedded images travel together. New files use version 2; existing version 1 drawings migrate when opened. No account is needed to open them.

SVG or PNG to share

The Export menu always downloads the current page. Choose a scalable SVG or a PNG at 2× resolution for a message, document or slide. Add item-ID labels when a vision model needs to connect an image back to the document. 

const editable = await board.export('json', { scope: 'doc' })
const vector = await board.export('svg', { padding: 32 })
const image = await board.export('png', {
  scope: 'viewport', scale: 2, labels: true,
})

Browser storage is a convenience, not a backup service. Remote images are subject to browser CORS rules. Custom HTML is represented safely in export; custom kinds can provide their own SVG output.

06 / ROOM TO GROW

Add only what you need.

A shape of your own

Register a custom kind with its own appearance, geometry and editing handles. The same shape can work in the live board and portable SVG exports.

HTML with clear boundaries

Supply a trusted sanitizer when your application needs HTML content. The document keeps ordinary text and structured data portable.

Keep extensions in application code. The document stores their kind name and data; opening a drawing never loads an executable callback.
